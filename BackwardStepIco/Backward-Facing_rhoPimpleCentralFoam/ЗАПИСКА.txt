---------------------Возможные причины
С учётом задач (QGD/реакционные солверы, гибридная параллелизация, ICX) наиболее вероятны следующие причины:

Слишком большой шаг по времени или высокий Courant. Max Co = 4.67 — это много для сжимаемых/реакционных солверов. Даже если PIMPLE делает несколько внутренних итераций, при сильных градиентах и реакциях схема может не «вытянуть» такой шаг.
Некорректные граничные условия для T или h. Особенно если используются профили/таблицы (ты ранее спрашивал про fixedProfile): при интерполяции или экстраполяции могут возникать отрицательные значения.
Ошибки в кастомных моделях (QGD, реакции, турбулентность). В форке QGDsolver могут быть формулы, которые при определённых условиях дают отрицательные величины (например, плотность, давление, энтальпия), а затем они попадают под корень.
NUMA‑дисбаланс и разные значения на границах поддоменов. Если на границе MPI‑доменов возникают резкие скачки (из‑за плохой балансировки или привязки процессов к нодам), то градиенты и дивергенции становятся огромными, и схема срывается.
Компиляторные оптимизации ICX. При -fp-model precise ICX может менять порядок операций, и в пограничных случаях это приводит к отрицательным значениям там, где GCC давал «почти ноль».
Проблемы с инициализацией. Если начальное поле T задано некорректно (локальные пики, отрицательные значения), то уже на первых шагах схема может уйти в нефизику.


------------------Как переключиться с RANS на LES
Замена в одном файле — constant/turbulenceProperties:

------------------Было (RANS, SST k-ω):

simulationType RAS;
RAS
{
    RASModel kOmegaSST;
    turbulence on;
    printCoeffs on;
}

---------------------Стало (LES, WALE):

simulationType LES;
LES
{
    LESModel WALE;
    delta cubeRootVol;
    turbulence on;
    printCoeffs on;

    WALECoeffs
    {
        Cw 0.325;
    }
    cubeRootVolCoeffs
    {
        deltaCoeff 1;
    }
}
