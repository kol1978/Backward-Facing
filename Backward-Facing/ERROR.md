## Ошибка 1 — `symmetryPlane` не плоский

### Сообщение OpenFOAM

```text
--> FOAM FATAL ERROR:
Symmetry plane 'frontAndBack' is not planar
At patch face #233824 with centre (0.0999 0.0919 0.0762)
the normal (0 0 1) differs from the average normal
(-1.8e-18 2.7e-18 -1.6e-20) by 1
Either split the patch into planar parts or use the symmetry patch type
Суть проблемы
Патч frontAndBack объявлен как symmetryPlane, но OpenFOAM обнаружил, что грани не лежат строго в одной плоскости. Даже минимальные численные отклонения (порядка 1e-18) приводят к отказу — symmetryPlane требует строгой планарности.

Причина возникновения
В 2D-кейсе с empty этой проверки нет — патч просто игнорируется.
При попытке использовать symmetryPlane (для перехода к квази-3D или 3D-LES) blockMesh с одной ячейкой по Z даёт микро-отклонения нормалей.
Типично для сеток, сгенерированных автоматически, особенно на NUMA-системах, где разные домены могут иметь разные округления координат.
Решение
Заменить тип патча с symmetryPlane на symmetry.

Тип symmetry не проверяет планарность, а просто обеспечивает зеркальную симметрию — этого достаточно для большинства задач обратного уступа.

text
// Было:
frontAndBack
{
    type symmetryPlane;
    ...
}

// Стало:
frontAndBack
{
    type symmetry;
    ...
}
⚠️ После замены — пересоздать сетку (blockMesh) и перезапустить расчёт.

Ошибка 2 — 2D LES: обратный каскад энергии
Ключевое замечание
«В 2D-постановке нет полноценного каскада энергии по масштабам: в двумерной турбулентности работает обратный каскад (энергия уходит в большие масштабы), а не прямой (как в 3D). Это фундаментально меняет физику. Подавляются важные типы вихревых взаимодействий: многие механизмы генерации и разрушения вихрей требуют трёх измерений.»

Что это значит
Это не ошибка компиляции и не баг OpenFOAM — это фундаментальное ограничение физики. В 2D турбулентность ведёт себя иначе, чем в реальности.

Даже если расчёт «сойдётся», количественные результаты будут отличаться от эксперимента Driver & Seegmiller:

Параметр	Ожидаемое отклонение
Длина рециркуляционной зоны	значительное
Профили скорости	заметное
Пульсации (rms)	качественно неверные
Связь с аппаратной конфигурацией
Даже при идеальной настройке NUMA (4 MPI × 4 OpenMP × 4 TBB) и компиляции под Intel ICX эта ошибка не исчезнет — она физическая. Никакие флаги -march=westmere, -fiopenmp или привязка рангов к нодам не исправят физику 2D-LES.

Предупреждение 3 — cubeRootVol delta в 2D
Сообщение
text
Выбор типа дельты LES cubeRootVol
--> Предупреждение FOAM:
Из функции void Foam::LESModels::cubeRootVolDelta::calcDelta()
Случай 2D, LES не совсем применим
Интерпретация
OpenFOAM явно предупреждает, что модель дельты cubeRootVol (характерный размер ячейки как кубический корень из объёма) используется в 2D-расчёте. Поскольку в 2D объём ячейки формально равен нулю (или очень мал из-за empty), дельта становится некорректной.

Практическое следствие
LES-модель будет работать, но масштаб подсеточной вязкости будет задан неверно. Это ещё один аргумент в пользу того, что 2D LES не годится для валидации.

Рекомендации по исправлению
Проблема	Решение	Совместимость
symmetryPlane не плоский	Заменить патч frontAndBack на тип symmetry в boundary и blockMeshDict	Все версии OpenFOAM (v12–v2606)
Физическая некорректность 2D LES	Перейти на 3D LES (минимум 3–5 ячеек по Z) или на 2D RANS (kOmegaSST, kEpsilon)	3D LES потребует больше памяти — NUMA-топология поможет при правильной декомпозиции
cubeRootVol в 2D	В 3D — использовать cubeRootVol; в 2D — не использовать LES	В 3D дельта корректна; в 2D LES не запускать
Сборка под Intel ICX	Проверить флаги -fiopenmp и -march=westmere в правилах wmake	Проверено для v2306/v2606 с Intel oneAPI
План действий
Шаг 1. Быстрое исправление патча (5 минут)
Открыть constant/polyMesh/boundary (или blockMeshDict).
Найти блок frontAndBack → заменить type symmetryPlane на type symmetry.
Пересоздать сетку: blockMesh.
Перезапустить расчёт. Ошибка not planar исчезнет.
Шаг 2. Выбор стратегии расчёта
Цель — валидация против эксперимента → единственный корректный путь: 3D LES (минимум 3–5 ячеек по Z, frontAndBack → symmetry или cyclic).
Цель — быстрая оценка / обучение → можно оставить 2D, но понимать: результаты качественные, не количественные.
Компромисс → 2D RANS (kOmegaSST) — физически корректно для 2D, даёт средние поля, пригодные для сравнения с экспериментом.
Шаг 3. Проверка декомпозиции (для 3D)
При переходе к 3D обязательно проверить:

decomposeParDict: метод hierarchical с правильным указанием количества доменов на NUMA-узел.
Запуск через mpirun с привязкой рангов к NUMA-нодам (избежать межнодального трафика памяти).
Схема: 4 MPI × 4 OpenMP × 4 TBB — пересчитать с учётом увеличения ячеек по Z.
Итог: Ошибка 1 решается заменой symmetryPlane → symmetry. Ошибка 2 и Предупреждение 3 требуют перехода к 3D LES или 2D RANS — 2D LES физически некорректен.
