f_scalar — читаемый эталон подынтегральной функции
В integrate_sse4 функция f(x) = x^2 зашита прямо в SSE-интринсики:

cpp
__m128d v_fx = _mm_mul_pd(v_x, v_x);   // это f(x) = x^2
Из этой строки неочевидно, что именно интегрируется — _mm_mul_pd просто умножает два вектора. f_scalar делает математику явной:

cpp
static inline double f_scalar(double x)
{
    return x * x;
}
Зачем это нужно:

Когда ты или кто-то другой через полгода откроет код, f_scalar сразу показывает: «интегрируем квадрат». В SSE-версии это пришлось бы расшифровывать обратно.
Если захочешь поменять подынтегральную функцию (например, sin(x) или exp(-x^2)), f_scalar — точка отсчёма: сначала пишешь скалярную версию, проверяешь, потом думаешь, как векторизовать.
В OpenFOAM-контексте это аналогично тому, как в солвере пишут источник тепла в читаемом виде (q = k * T * T), а потом компилятор сам разворачивает его в инструкции.
integrate_scalar — эталон алгоритма без векторизации
cpp
double integrate_scalar(double (*func)(double, void*), void *params,
                         double a, double b)
{
    const double half_len = 0.5 * (b - a);
    const double midpoint = 0.5 * (a + b);
    double sum = 0.0;
    for (int i = 0; i < 8; i++)
    {
        double x = half_len * gl_nodes[i] + midpoint;
        sum += gl_weights[i] * func(x, params);
    }
    return half_len * sum;
}
Зачем это нужно:

1. Понятность алгоритма. Квадратура Гаусса–Лежандра в скалярном виде читается как учебная формула: берём узлы, масштабируем, умножаем на веса, суммируем. В SSE-версии та же логика размыта по _mm_mul_pd, _mm_add_pd, _mm_hadd_pd — нужно знать интринсики, чтобы понять, что происходит. integrate_scalar — это «человеческое описание» того же алгоритма.

2. Точка сравнения для отладки. Если SSE-версия выдаёт странный результат, можно вызвать integrate_scalar с теми же пределами и сравнить. Если совпадает — ошибка не в алгоритме, а где-то в вызове. Если не совпадает — баг в векторизации.

3. Fallback для сложных функций. integrate_sse4 работает только для f(x) = x^2 — возведение в квадрат зашито жёстко. Если понадобится интегрировать функцию с ветвлением (например, кусочно-линейную аппроксимацию поля температуры из OpenFOAM), SSE-векторизация сломается. integrate_scalar принимает указатель на функцию — func(x, params) — и работает с любой f(x), включая те, где есть if, циклы, вызовы GSL или OpenFOAM-полей.

4. Шаблон для расширения. Если захочешь добавить 16- или 32-точечную квадратуру, логика та же: заменить массив gl_nodes/gl_weights на больший. В скалярной версии это тривиально — поменял константы. В SSE-версии придётся пересчитывать количество векторных итераций и, возможно, переходить на AVX (4 double за такт вместо 2).

Конкретный пример из OpenFOAM
Представь, что ты считаешь массовый расход через сечение в rhoPimpleCentralFoam:

cpp
// Массовый расход = интеграл (rho * U_normal) по площади грани
// rho и U_normal зависят от локальных значений полей — это не x^2,
// это интерполяция из ячеек + уравнение состояния
integrate_sse4 здесь не сработает — функция не является простым полиномом.
integrate_scalar — сработает: передаёшь указатель на функцию, которая читает rho[i] и U[i].normal(), и получаешь результат.
Именно поэтому обе функции остаются в коде: одна — для максимальной скорости на простых функциях, другая — для универсальности на сложных.
----------------------------------------------------Способы распараллеливания
Код вычисляет ∫x^2 dx адаптивной квадратурой Гаусса–Кронрода (QAGS).
Сама функция gsl_integration_qags — последовательная: адаптивный алгоритм дробит интервал по результатам оценки ошибки, и каждое следующее подразделение зависит от предыдущего. Параллелить нужно на уровне выше.

1. Декомпозиция области + OpenMP (самый практичный)
Делим [0,1] на N подынтервалов, каждый поток интегрирует свой кусок в отдельном gsl_integration_workspace, результаты суммируем.

-----------------------------------------------
#include <gsl/gsl_integration.h>
#include <omp.h>
#include <stdio.h>

double f(double x, void *params) {
    return x * x;
}

int main() {
    const int N = 8;                        // число потоков
    const double a = 0.0, b = 1.0;
    const double h = (b - a) / N;
    double total = 0.0;

    #pragma omp parallel for reduction(+:total) num_threads(N)
    for (int i = 0; i < N; i++) {
        double local_a = a + i * h;
        double local_b = a + (i + 1) * h;
        double result, error;

        // У каждого потока — свой workspace (GSL не потокобезопасен глобально)
        gsl_integration_workspace *w = gsl_integration_workspace_alloc(1000);
        gsl_function F;
        F.function = &f;
        F.params = NULL;

        gsl_integration_qags(&F, local_a, local_b, 0, 1e-7, 1000, w, &result, &error);
        total += result;

        gsl_integration_workspace_free(w);
    }

    printf("Result: %.15f\n", total);
    return 0;
}
Эффективность:

Для гладких функций (как x2) — близка к линейной (ускорение≈N), но бессмысленна: один интеграл считается за микросекунды, накладные расходы на создание потоков и workspace_alloc превысят время счёта.
Для жёстких функций (oscillatory, singular) — дисбаланс нагрузки: один подынтервал может потребовать 900 итераций, а соседний — 20. Потоки простаивают. Решение — динамическое планирование (schedule(dynamic)), но тогда теряется локальность кэша.
Для конкретно x2 адаптивный алгоритм сходится за 1–2 функции-оценки на подынтервал, так что параллелизм здесь — чистый overhead.
2. Множество независимых интегралов (embarrassingly parallel)
Если задача — считать много интегралов (например, для каждой ячейки сетки OpenFOAM), каждый независим:
--------------------------------
#pragma omp parallel for num_threads(N) schedule(dynamic)
for (int i = 0; i < M; i++) {
    gsl_integration_workspace *w = gsl_integration_workspace_alloc(1000);
    // ... интеграл i ...
    gsl_integration_workspace_free(w);
}
--------------------------------------------
Эффективность:
Близка к идеальной (≈N на N ядрах), если все интегралы сравнимы по трудоёмкости.
schedule(dynamic) сглаживает дисбаланс, если одни интегралы труднее других.
Это единственный сценарий, где распараллеливание GSL-интегрирования реально даёт выигрыш.

3. MPI (для распределённых систем / кластеров)
Аналогично декомпозиции области, но через MPI:
-----------------------------------------------
int rank, size;
MPI_Init(NULL, NULL);
MPI_Comm_rank(MPI_COMM_WORLD, &rank);
MPI_Comm_size(MPI_COMM_WORLD, &size);

double local_a = a + rank * (b - a) / size;
double local_b = a + (rank + 1) * (b - a) / size;
double local_result, error;

gsl_integration_workspace *w = gsl_integration_workspace_alloc(1000);
gsl_integration_qags(&F, local_a, local_b, 0, 1e-7, 1000, w, &local_result, &error);

double global_result;
MPI_Reduce(&local_result, &global_result, 1, MPI_DOUBLE, MPI_SUM, 0, MPI_COMM_WORLD);
---------------------------------------------------

Эффективность:

Для одного интеграла — нулевая (накладные расходы MPI на старте/редукции больше времени счёта).
Для массива из тысяч интегралов — близкая к линейной на масштабе десятков/сотен узлов.

GSL — потокобезопасна, но с оговорками
Согласно официальной документации:

All the functions are thread-safe, in the sense that they do not use static variables. Memory is always associated with objects and not with functions. For functions which use workspace objects as temporary storage the workspaces should be allocated on a per-thread basis.

Правила использования в многопотоке:

Workspace — на каждый поток свой. gsl_integration_workspace, gsl_matrix, gsl_vector — всё это объекты с памятью. Если два потока работают с одним workspace одновременно — data race. Каждый поток должен alloc/free свой.
Таблицы (read-only) — общие. Константные lookup-таблицы (например, узлы Гаусса–Кронрода) объявлены const и могут читаться несколькими потоками одновременно.
Глобальные переменные — инициализировать один раз. gsl_set_error_handler, gsl_set_error_handler_off — настраиваются в главном потоке до старта рабочих. Менять их из рабочих потоков нельзя.
Алиасинг памяти запрещён. Если два аргумента указывают на пересекающуюся память и хотя бы один модифицируется — результат undefined.
Применительно к OpenFOAM: GSL можно встроить в солвер, если:

Каждый MPI-процесс (и каждый OpenMP-поток внутри него) создаёт свои gsl_integration_workspace.
Обработчик ошибок настраивается один раз на процесс в main() до распараллеливания.
В цикле по ячейкам сетки (forAll(U, cellI)) вызовы GSL безопасны, если workspace уже аллоцирован.
cpp
// Схема интеграции в OpenFOAM-солвер
#pragma omp parallel
{
    // Каждый поток — свой workspace
    gsl_integration_workspace* w = gsl_integration_workspace_alloc(1000);

    #pragma omp for
    for (int i = 0; i < nCells; i++) {
        double result, error;
        // ... вызов gsl_integration_qags ...
    }

    gsl_integration_workspace_free(w);
}
SQLite — три режима потокобезопасности
Согласно официальной документации, SQLite поддерживает три режима:

Режим	Флаг компиляции	Потокобезопасность	Производительность
Single-thread	SQLITE_THREADSAFE=0	Нет	Максимальная
Multi-thread	SQLITE_THREADSAFE=2	Да, если каждый поток — своё соединение	Хорошая
Serialized	SQLITE_THREADSAFE=1 (по умолчанию)	Полная (через мьютексы)	Узкое место при записи

Ключевые правила:

В multi-thread режиме: несколько потоков могут работать, но один sqlite3* handle — только в одном потоке. Включается через sqlite3_config(SQLITE_CONFIG_MULTITHREAD) или SQLITE_OPEN_NOMUTEX при открытии.
В serialized режиме: один sqlite3* можно шарить между потоками, но все вызовы сериализуются через мьютекс — фактического параллелизма нет.
WAL-режим (PRAGMA journal_mode=WAL) позволяет множеству читателей и одному писателю одновременно — лучшая производительность для записи из нескольких потоков.
Fork safety: sqlite3* handle нельзя передавать в дочерний процесс после fork(). Нужно открывать соединение после fork.
Применительно к OpenFOAM: SQLite можно использовать для логирования результатов расчёта (запись метрик, временных рядов, контрольных точек), но:

Гибридный пример MPI + OpenMP для всех трёх задач GSL. Каждый MPI-процесс обрабатывает свою порцию данных, внутри процесса OpenMP распараллеливает по потокам, каждый поток имеет собственный gsl_integration_workspace.

c
/*
 * Гибридное распараллеливание: MPI + OpenMP + GSL
 *
 * Компиляция:
 *   mpicc -fopenmp hybrid_gsl.c -lgsl -lgslcblas -lm -o hybrid_gsl
 *
 * Запуск (2 процесса, по 6 потоков в каждом):
 *   mpirun -np 2 ./hybrid_gsl 6
 *
 * Запуск (4 процесса, по 12 потоков — под твой NUMA-сервер):
 *   mpirun -np 4 ./hybrid_gsl 12
 *
 * Аргумент argv[1] — число OpenMP-потоков на каждый MPI-процесс.
 * Если не задан — используется omp_get_max_threads().
 */

#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#include <mpi.h>
#include <omp.h>

#include <gsl/gsl_integration.h>
#include <gsl/gsl_matrix.h>
#include <gsl/gsl_linalg.h>
#include <gsl/gsl_statistics.h>

/* ================================================================
 * ИНТЕГРИРУЕМАЯ ФУНКЦИЯ
 * ================================================================ */

/* Подынтегральная функция: f(x) = x^2
 * params — указатель на параметры функции (здесь не используется,
 * но нужен по сигнатуре GSL).
 * Эта функция чистая (pure): не имеет побочных эффектов,
 * потокобезопасна по определению — её можно вызывать
 * из любого количества потоков одновременно. */
double my_function(double x, void *params) {
    (void)params; /* подавляем предупреждение о неиспользуемом параметре */
    return x * x;
}

/* ================================================================
 * ЗАДАЧА 1: Численное интегрирование (гибрид MPI + OpenMP)
 * ================================================================
 *
 * Стратегия:
 * - Делим отрезок [a, b] на N подынтервалов (N = mpi_size * omp_threads).
 * - Каждый MPI-процесс получает свою долю подынтервалов.
 * - Внутри процесса OpenMP-потоки делят подынтервалы между собой.
 * - Каждый поток создаёт СОБСТВЕННЫЙ gsl_integration_workspace
 *   (GSL требует это для потокобезопасности).
 * - Локальные результаты суммируются через OpenMP reduction,
 *   затем редуцируются через MPI_Reduce.
 */

void task_integration(int mpi_rank, int mpi_size, int n_threads) {
    const double a = 0.0;
    const double b = 1.0;
    const double eps_abs = 0.0;
    const double eps_rel = 1e-7;
    const int max_intervals = 1000;

    /* Общее число подынтервалов: mpi_size * n_threads.
     * Каждый подынтервал интегрируется отдельно, результаты суммируются.
     * Так достигается линейное ускорение при хорошем балансе нагрузки. */
    int total_subintervals = mpi_size * n_threads;

    /* Подынтервалы распределены между MPI-процессами ленточным способом:
     * процесс 0 → подынтервалы [0, n_threads)
     * процесс 1 → подынтервалы [n_threads, 2*n_threads)
     * и т.д.
     * Ширина одного подынтервала: */
    double h = (b - a) / total_subintervals;

    /* Границы подынтервалов для текущего MPI-процесса */
    int my_start = mpi_rank * n_threads;
    int my_end   = my_start + n_threads;

    /* Локальная сумма интеграла (для OpenMP reduction) */
    double local_sum = 0.0;

    /* Каждый поток работает со своим workspace.
     * Создаём массив workspace-ов: по одному на поток. */
    gsl_integration_workspace **workspaces =
        malloc(n_threads * sizeof(gsl_integration_workspace *));

    for (int t = 0; t < n_threads; t++) {
        workspaces[t] = gsl_integration_workspace_alloc(max_intervals);
    }

    /* Готовим gsl_function (общая для всех потоков,
     * т.к. функция чистая и не имеет состояния) */
    gsl_function F;
    F.function = &my_function;
    F.params = NULL;

    /* OpenMP-параллельный цикл по подынтервалам текущего MPI-процесса.
     * reduction(+:local_sum) — OpenMP автоматически суммирует
     * локальные копии local_sum из каждого потока в общую. */
    #pragma omp parallel for reduction(+:local_sum) num_threads(n_threads)
    for (int i = my_start; i < my_end; i++) {
        /* Получаем номер текущего потока, чтобы взять свой workspace */
        int tid = omp_get_thread_num();

        double sub_a = a + i * h;
        double sub_b = a + (i + 1) * h;
        double result, error;

        /* Интегрируем на своём подынтервале своим workspace.
         * Потокобезопасно: workspace не пересекается с другими потоками,
         * gsl_function F — read-only (указатель на чистую функцию). */
        gsl_integration_qags(&F, sub_a, sub_b,
                             eps_abs, eps_rel, max_intervals,
                             workspaces[tid], &result, &error);

        local_sum += result;
    }

    /* Освобождаем workspace-и */
    for (int t = 0; t < n_threads; t++) {
        gsl_integration_workspace_free(workspaces[t]);
    }
    free(workspaces);

    /* MPI-редукция: суммируем локальные суммы со всех процессов */
    double global_sum = 0.0;
    MPI_Reduce(&local_sum, &global_sum, 1, MPI_DOUBLE,
               MPI_SUM, 0, MPI_COMM_WORLD);

    if (mpi_rank == 0) {
        printf("=== Задача 1: Численное интегрирование ===\n");
        printf("Отрезок: [%.1f, %.1f]\n", a, b);
        printf("MPI-процессов: %d, OpenMP-потоков на процесс: %d\n",
               mpi_size, n_threads);
        printf("Всего подынтервалов: %d\n", total_subintervals);
        printf("Результат: %.15f (точное значение: 0.333333...)\n",
               global_sum);
        printf("\n");
    }
}

/* ================================================================
 * ЗАДАЧА 2: Решение СЛАУ (только MPI, без OpenMP)
 * ================================================================
 *
 * Стратегия:
 * - Каждое решение СЛАУ — независимая задача.
 * - Распределяем матрицы по MPI-процессам (по одной на процесс).
 * - OpenMP здесь не нужен: gsl_linalg_HH_solve для 2x2 тривиален.
 *   (Для больших матриц можно использовать BLAS с многопоточностью,
 *    но GSL BLAS — однопоточный.)
 * - Если матриц больше, чем процессов — цикл по матрицам внутри процесса.
 */

/* Структура для хранения матрицы и правой части */
typedef struct {
    double m00, m01, m10, m11;  /* элементы матрицы 2x2 */
    double b0, b1;               /* правая часть */
} System2x2;

void task_linear_algebra(int mpi_rank, int mpi_size) {
    /* Набор систем для решения.
     * В реальной задаче (например, в OpenFOAM) это могут быть
     * локальные матрицы для каждой ячейки сетки. */
    System2x2 systems[] = {
        {2.0, 1.0, 1.0, 3.0, 1.0, 2.0},   /* система 0 */
        {1.0, 4.0, 2.0, 1.0, 3.0, 1.0},   /* система 1 */
        {3.0, 2.0, 1.0, 5.0, 2.0, 4.0},   /* система 2 */
        {4.0, 1.0, 1.0, 2.0, 1.0, 3.0},   /* система 3 */
    };
    int n_systems = sizeof(systems) / sizeof(systems[0]);

    /* Каждый MPI-процесс решает системы с индексами
     * rank, rank+size, rank+2*size, ... (циклическое распределение) */
    double my_results[2 * 4];  /* до 4 систем, по 2 неизвестных */
    int my_count = 0;

    for (int s = mpi_rank; s < n_systems; s += mpi_size) {
        gsl_matrix *m = gsl_matrix_alloc(2, 2);
        gsl_vector *b = gsl_vector_alloc(2);
        gsl_vector *x = gsl_vector_alloc(2);

        gsl_matrix_set(m, 0, 0, systems[s].m00);
        gsl_matrix_set(m, 0, 1, systems[s].m01);
        gsl_matrix_set(m, 1, 0, systems[s].m10);
        gsl_matrix_set(m, 1, 1, systems[s].m11);
        gsl_vector_set(b, 0, systems[s].b0);
        gsl_vector_set(b, 1, systems[s].b1);

        /* gsl_linalg_HH_solve решает Ax = b методом Хаусхолдера.
         * ВАЖНО: функция МОДИФИРУЕТ матрицу m (разрушает исходные данные),
         * поэтому при распараллеливании каждый процесс должен иметь
         * свою копию матрицы — что у нас и есть. */
        gsl_linalg_HH_solve(m, b, x);

        my_results[my_count * 2 + 0] = gsl_vector_get(x, 0);
        my_results[my_count * 2 + 1] = gsl_vector_get(x, 1);
        my_count++;

        gsl_matrix_free(m);
        gsl_vector_free(b);
        gsl_vector_free(x);
    }

    /* Собираем результаты на процессе 0 через MPI_Gatherv.
     * Для простоты используем MPI_Gather с фиксированным размером. */
    double all_results[2 * 4];
    int results_per_process = 2 * 4;  /* максимум 4 систем * 2 значения */
    MPI_Gather(my_results, results_per_process, MPI_DOUBLE,
                all_results, results_per_process, MPI_DOUBLE,
                0, MPI_COMM_WORLD);

    if (mpi_rank == 0) {
        printf("=== Задача 2: Решение СЛАУ ===\n");
        printf("MPI-процессов: %d\n", mpi_size);
        for (int s = 0; s < n_systems; s++) {
            /* Индекс процесса, который решал систему s */
            int src_rank = s % mpi_size;
            /* Позиция в буфере all_results */
            int idx = (s / mpi_size);  /* порядковый номер системы у этого процесса */
            /* Результаты лежат подряд: all_results[src_rank * 8 + idx*2 ...] */
            double x0 = all_results[src_rank * results_per_process + idx * 2 + 0];
            double x1 = all_results[src_rank * results_per_process + idx * 2 + 1];
            printf("Система %d (процесс %d): x0 = %.6f, x1 = %.6f\n",
                   s, src_rank, x0, x1);
        }
        printf("\n");
    }
}

/* ================================================================
 * ЗАДАЧА 3: Статистика (гибрид MPI + OpenMP)
 * ================================================================
 *
 * Стратегия:
 * - Генерируем большой массив данных, распределённый по MPI-процессам.
 * - Каждый процесс считает локальные сумму и сумму квадратов
 *   через OpenMP reduction.
 * - Затем MPI_Reduce собирает глобальные сумму и сумму квадратов.
 * - Финальные mean и variance считаются на rank 0.
 *
 * gsl_stats_mean и gsl_stats_variance — однопроходные,
 * но нам нужна двухуровневая редукция (MPI + OpenMP), поэтому
 * мы считаем сумму и сумму квадратов вручную, а GSL используем
 * для локальной статистики (на каждом процессе).
 */

void task_statistics(int mpi_rank, int mpi_size, int n_threads) {
    /* Размер массива данных на каждый MPI-процесс.
     * В реальной задаче это может быть часть сетки OpenFOAM,
     * распределённая по процессам через decomposePar. */
    int local_n = 10000;
    double *local_data = malloc(local_n * sizeof(double));

    /* Заполняем данными (синтетическими, с seed от rank).
     * Каждый процесс генерирует свою долю независимо. */
    unsigned int seed = 42 + mpi_rank * 1000;

    /* Генерация данных: равномерное распределение + сдвиг для разных процессов.
     * Используем простейший ГСЧ (не GSL, чтобы не усложнять).
     * В реальном коде здесь были бы поля OpenFOAM. */
    #pragma omp parallel for num_threads(n_threads)
    for (int i = 0; i < local_n; i++) {
        /* Линейный конгруэнтный ГСЧ — простой и потокобезопасный,
         * т.к. каждый поток пишет в свой элемент массива. */
        seed = (1103515245 * seed + 12345) & 0x7fffffff;
        local_data[i] = (double)(seed % 1000) / 100.0 + mpi_rank * 10.0;
    }

    /* Локальная статистика через GSL (на каждом процессе).
     * gsl_stats_mean / gsl_stats_variance — read-only функции,
     * потокобезопасны, но мы вызываем их один раз на процесс,
     * а не из OpenMP-параллельного региона. */
    double local_mean = gsl_stats_mean(local_data, 1, local_n);
    double local_variance = gsl_stats_variance(local_data, 1, local_n);

    /* Двухуровневая редукция для глобальной статистики.
     * Уровень 1 (OpenMP): каждый поток считает свою частичную сумму
     *   и сумму квадратов, reduction их складывает.
     * Уровень 2 (MPI): MPI_Reduce суммирует по процессам. */

    double local_sum = 0.0;
    double local_sum_sq = 0.0;

    #pragma omp parallel for reduction(+:local_sum, local_sum_sq) num_threads(n_threads)
    for (int i = 0; i < local_n; i++) {
        local_sum += local_data[i];
        local_sum_sq += local_data[i] * local_data[i];
    }

    /* MPI-редукция: суммируем суммы и суммы квадратов */
    double global_sum = 0.0;
    double global_sum_sq = 0.0;
    MPI_Reduce(&local_sum, &global_sum, 1, MPI_DOUBLE, MPI_SUM, 0, MPI_COMM_WORLD);
    MPI_Reduce(&local_sum_sq, &global_sum_sq, 1, MPI_DOUBLE, MPI_SUM, 0, MPI_COMM_WORLD);

    /* Общее число элементов по всем процессам */
    int total_n = local_n * mpi_size;

    if (mpi_rank == 0) {
        /* Глобальное среднее и дисперсия */
        double global_mean = global_sum / total_n;
        double global_variance = global_sum_sq / total_n
                                 - global_mean * global_mean;

        printf("=== Задача 3: Статистика ===\n");
        printf("MPI-процессов: %d, OpenMP-потоков: %d\n", mpi_size, n_threads);
        printf("Размер массива: %d элементов (по %d на процесс)\n",
               total_n, local_n);
        printf("Локальная статистика (процесс 0): mean = %.4f, var = %.4f\n",
               local_mean, local_variance);
        printf("Глобальная статистика:           mean = %.4f, var = %.4f\n",
               global_mean, global_variance);
        printf("\n");
    }

    free(local_data);
}

/* ================================================================
 * MAIN
 * ================================================================ */

int main(int argc, char **argv) {
    /* ----- Инициализация MPI ----- */
    /* MPI_THREAD_MULTIPLE — максимальный уровень потокобезопасности MPI.
     * Нужен, если потоки OpenMP вызывают MPI-функции одновременно.
     * MPI_THREAD_FUNNELED — если MPI вызывает только главный поток.
     * Здесь мы используем MPI только между OpenMP-регионами,
     * поэтому MPI_THREAD_FUNNELED достаточно, но MULTIPLE — безопаснее. */
    int provided;
    MPI_Init_thread(&argc, &argv, MPI_THREAD_MULTIPLE, &provided);

    if (provided < MPI_THREAD_FUNNELED) {
        fprintf(stderr, "MPI не поддерживает потокобезопасность\n");
        MPI_Abort(MPI_COMM_WORLD, 1);
    }

    int mpi_rank, mpi_size;
    MPI_Comm_rank(MPI_COMM_WORLD, &mpi_rank);
    MPI_Comm_size(MPI_COMM_WORLD, &mpi_size);

    /* ----- Определение числа OpenMP-потоков ----- */
    int n_threads;
    if (argc > 1) {
        n_threads = atoi(argv[1]);
        if (n_threads < 1) n_threads = 1;
    } else {
        n_threads = omp_get_max_threads();
    }
    omp_set_num_threads(n_threads);

    /* Отключаем обработчик ошибок GSL, чтобы при ошибке GSL не вызывал abort()
     * (который убил бы весь MPI-процесс, а не только один поток).
     * Вместо этого функции GSL вернут код ошибки, который мы можем обработать.
     * ВАЖНО: вызывается ОДИН РАЗ в главном потоке до распараллеливания. */
    gsl_set_error_handler_off();

    if (mpi_rank == 0) {
        printf("========================================\n");
        printf("Гибридное распараллеливание MPI + OpenMP\n");
        printf("========================================\n");
        printf("MPI-процессов:    %d\n", mpi_size);
        printf("OpenMP-потоков:   %d\n", n_threads);
        printf("Всего ядер:       %d\n", mpi_size * n_threads);
        printf("MPI thread level: ");
        switch (provided) {
            case MPI_THREAD_SINGLE:     printf("SINGLE\n");     break;
            case MPI_THREAD_FUNNELED:   printf("FUNNELED\n");   break;
            case MPI_THREAD_SERIALIZED: printf("SERIALIZED\n"); break;
            case MPI_THREAD_MULTIPLE:   printf("MULTIPLE\n");   break;
            default:                    printf("UNKNOWN\n");
        }
        printf("========================================\n\n");
    }

    /* Синхронизация перед началом задач (чтобы вывод был аккуратным) */
    MPI_Barrier(MPI_COMM_WORLD);

    /* Задача 1: интегрирование (MPI + OpenMP) */
    task_integration(mpi_rank, mpi_size, n_threads);

    MPI_Barrier(MPI_COMM_WORLD);

    /* Задача 2: СЛАУ (только MPI) */
    task_linear_algebra(mpi_rank, mpi_size);

    MPI_Barrier(MPI_COMM_WORLD);

    /* Задача 3: статистика (MPI + OpenMP) */
    task_statistics(mpi_rank, mpi_size, n_threads);

    if (mpi_rank == 0) {
        printf("========================================\n");
        printf("Все задачи завершены.\n");
        printf("========================================\n");
    }

    MPI_Finalize();
    return 0;
}

Ключевые решения и почему именно так
1. Workspace на каждый поток
c
gsl_integration_workspace **workspaces = malloc(n_threads * ...);
GSL хранит промежуточные данные (подынтервалы, оценки ошибок) в workspace. Если два потока пишут в один workspace — data race, результат непредсказуем. Массив workspace-ов гарантирует изоляцию.

2. gsl_set_error_handler_off() до распараллеливания
Обработчик ошибок GSL по умолчанию вызывает abort(), что убивает весь MPI-процесс (все потоки). Отключение позволяет обрабатывать ошибки мягко. Вызывается один раз в main до создания потоков.

3. MPI_THREAD_MULTIPLE с проверкой
Запрашиваем максимальную потокобезопасность MPI. Если реализация не поддерживает — падаем с понятной ошибкой, а не с гонкой данных.

4. reduction(+:...) вместо ручной синхронизации
c
#pragma omp parallel for reduction(+:local_sum)
OpenMP автоматически создаёт локальную копию local_sum в каждом потоке, накапливает, а после цикла атомарно суммирует. Без reduction потребовался бы #pragma omp atomic на каждой итерации — на порядки медленнее.

5. Почему СЛАУ без OpenMP
gsl_linalg_HH_solve для матрицы 2×2 выполняется за несколько операций. Создание OpenMP-потоков для этого — чистый overhead. Для больших матриц (1000×1000+) имело бы смысл использовать BLAS с многопоточностью, но GSL BLAS — однопоточный.

6. Двухуровневая редукция в статистике
text
Потоки → OpenMP reduction → локальная сумма → MPI_Reduce → глобальная сумма
Это классическая схема для гибридного MPI+OpenMP: сначала суммируем локально (быстро, в общей памяти), потом — по сети (медленно, только один раз).

#include <stdio.h>
#include <gsl/gsl_integration.h>
#include <gsl/gsl_matrix.h>
#include <gsl/gsl_linalg.h>
#include <gsl/gsl_statistics.h>

double my_function(double x, void *params) {
    return x*x;
}

int main() {
    // численное интегрирование
    gsl_integration_workspace *workspace = gsl_integration_workspace_alloc(1000);
    gsl_function F;
    F.function = &my_function;
    double result, error;
    gsl_integration_qags(&F, 0, 1, 0, 1e-7, 1000, workspace, &result, &error);
    printf("Integral result: %g, error: %g\n", result, error);
    gsl_integration_workspace_free(workspace);

    // решение системы линейных уравнений
    gsl_matrix *m = gsl_matrix_alloc(2, 2);
    gsl_vector *b = gsl_vector_alloc(2);
    gsl_vector *x = gsl_vector_alloc(2);

    gsl_matrix_set(m, 0, 0, 2.0);
    gsl_matrix_set(m, 0, 1, 1.0);
    gsl_matrix_set(m, 1, 0, 1.0);
    gsl_matrix_set(m, 1, 1, 3.0);
    gsl_vector_set(b, 0, 1.0);
    gsl_vector_set(b, 1, 2.0);

    gsl_linalg_HH_solve(m, b, x);

    printf("Solution: x0 = %g, x1 = %g\n", gsl_vector_get(x, 0), gsl_vector_get(x, 1));

    gsl_matrix_free(m);
    gsl_vector_free(b);
    gsl_vector_free(x);

    // статистический анализ
    double data[] = {17.0, 15.0, 23.0, 7.0, 9.0, 13.0};
    double mean = gsl_stats_mean(data, 1, 6);
    double variance = gsl_stats_variance(data, 1, 6);
    printf("Mean: %g, Variance: %g\n", mean, variance);

    return 0;
}
