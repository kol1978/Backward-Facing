Шаг 2. Вытащить всё с сервера (безопасный способ)

# Сначала получаем изменения с сервера, но НЕ применяем их
git fetch origin

Эта команда скачивает данные из удалённого репозитория, но ничего не меняет в твоих локальных файлах. Полностью безопасна.

Шаг 3. Восстановить конкретные файлы из репозитория
Если испорчены только некоторые файлы (например, ERROR.md и blockMeshDict):

# Восстановить один файл из последнего коммита
git checkout -- ERROR.md

# Восстановить несколько файлов
git checkout -- ERROR.md constant/polyMesh/boundary system/blockMeshDict
Флаг -- означает «это имена файлов, а не ветки». Git заменит локальные версии на версии из последнего коммита.

Шаг 4. Восстановить ВСЕ файлы (если испорчено много)
Если локально много изменений и ты хочешь вернуть всё к состоянию на сервере:

# Отменить все локальные изменения, не закоммиченные ранее
git checkout -- .

# Или жёстко сбросить к состоянию последнего коммита:
git reset --hard HEAD
⚠️ Внимание: git reset --hard удалит ВСЕ незакоммиченные изменения безвозвратно. Используй, только если уверен, что локальные правки не нужны.

Шаг 5. Если локальные коммиты тоже нужно откатить
Если ты уже сделал коммиты с ошибочными изменениями и хочешь вернуть всё к состоянию на сервере:

bash
# Посмотреть историю коммитов
git log --oneline -10

# Увидишь что-то вроде:
# a1b2c3d (HEAD -> main) Мои ошибочные правки
# d4e5f6a (origin/main) Последний правильный коммит на сервере

# Откатиться к состоянию на сервере:
git reset --hard origin/main
⚠️ Это удалит все локальные коммиты после origin/main и заменит файлы на серверные версии.

Шаг 6. Если есть незакоммиченные файлы, которые нужно сохранить
Если среди локальных файлов есть новые файлы, которых нет на сервере, и ты не хочешь их потерять:

bash
# Спрятать все локальные изменения в "карман"
git stash

# Теперь файлы вернулись к состоянию последнего коммита
# Проверь:
git status

# Если нужно вернуть спрятанные изменения:
git stash pop

# Если понял, что спрятанное не нужно:
